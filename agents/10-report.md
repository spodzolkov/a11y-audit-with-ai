# Етап 10 — Report (фінальний звіт аудиту)

## Мета
Сформувати читабельний фінальний звіт аудиту доступності на основі консолідованих знахідок: зведення, знахідки за серйозністю, пріоритезований план рекомендацій. Виправлення НЕ виконуються — лише рекомендації для команди.

## Вхідні дані
- `output/08-consolidation.md` — консолідовані знахідки та scoring.
- `docs/wcag-2.2-checklist.md` — для секції «Відповідність WCAG 2.2 AA»: у звіті для кожного порушеного SC наведи посилання на специфікацію та Understanding (з чек-листа) і приклад виправлення.
- `output/09-bug-reports.md` (опційно): якщо етап 9 виконано — у звіті для кожного `FINDING-NNN` додай посилання на згенерований баг-репорт (`BUG-NNN`); додай секцію «Баг-репорти» зі зведенням (скільки баг-репортів сформовано у `output/09-bug-reports.md`).

## Інструменти
- `read_file` — читання консолідації та баг-репортів.

## Алгоритм виконання
1. Прочитай `08-consolidation.md`; якщо існує `09-bug-reports.md` — прочитай і його (лише для секції «Баг-репорти»; вміст знахідок не змінюється).
2. Побудуй Executive Summary: A11y health, total findings, weighted score, розподіли.
3. Впорядкуй знахідки за серйозністю (critical → serious → moderate → minor).
4. Для кожної знахідки виведи всі поля структурованого формату + рекомендацію.
5. Сформуй **пріоритезований план дій** (що виправляти першим) — як рекомендації, без автоматичних змін.
6. Додай секцію відповідності WCAG 2.2 AA: перелік порушених success criteria.
7. За потреби додай CSV-експорт знахідок у `output/audit-findings.csv`.
8. Додай розділ «Рекомендації поза WCAG 2.2 AA» зі знахідками секції `## Поза цільовим стандартом` консолідації (без впливу на score і стан).
9. **Чекліст ручної перевірки** для кожної знахідки з `confidence` не `high`, а також для всіх знахідок, виявлених лише accessibility-снапшотом (без реального скрінрідера) по SC 1.3.1, 2.4.3, 4.1.2, 4.1.3, і знахідок reflow/масштабування (1.4.4, 1.4.10, 1.4.12). Для кожної:
   - сценарій NVDA + Chrome або Firefox (Windows) і, за наявності, JAWS: стартовий стан, конкретні клавіші (Tab, Shift+Tab, Enter, Space, Escape, стрілки, NVDA+T, H, D, F7 тощо), що очікується почути/побачити;
   - для візуальних SC — візуальна перевірка: zoom 200% і 400% у браузері (1280 px), ширина 320 CSS px, Text Spacing bookmarklet для 1.4.12;
   - критерій підтвердження/спростування і що змінити в знахідці (severity, confidence) за результатом.
   Чекліст — інструкція для людини; результати ручної перевірки пайплайн не вигадує.

  Проблема / Вплив / Рекомендація

| FINDING-008 | 1.4.10 | medium | Chrome, ширина 320 px / zoom 400% | ... | ... | ... |

## Примітка
Цей звіт лише фіксує проблеми та рекомендації. Виправлення виконує команда вручну — пайплайн змін не вносить.

## Acceptance Criteria
- [ ] Сформовано Executive Summary (health, total, weighted score, розподіли).
- [ ] Знахідки впорядковано за серйозністю з усіма полями.
- [ ] Додано секцію відповідності WCAG 2.2 AA (перелік порушених SC).
- [ ] Сформовано пріоритезований план дій як рекомендації (без автоматичних змін).
- [ ] Збережено id знахідок для traceability до консолідації.
- [ ] Знахідки поза стандартом — окремим розділом, без впливу на score.
- [ ] Чекліст ручної перевірки охоплює всі знахідки з confidence не high і знахідки, виявлені лише снапшотом (SC 1.3.1, 2.4.3, 4.1.2, 4.1.3) або стосуються reflow/масштабування.
- [ ] Файл `output/10-audit-report.md` створено; код/документи не змінювались.

- Правила та формат — skill `#Accessibility Audit Rules`.
