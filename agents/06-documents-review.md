# Етап 6 — Documents Review (ревʼю документів)

## Мета
Перевірити доступність офісних документів і PDF/ePub у scope. Тільки виявлення проблем і рекомендації — без ремедіації файлів.

## Вхідні дані
- `output/01-discovery.md` — перелік документів (.docx/.xlsx/.pptx/.pdf/.epub).
- Чек-лист критеріїв: `docs/wcag-2.2-checklist.md` (розділ «Документи» з відповідністю форматів до SC; у кожній знахідці вказуй `checklistRef`, приклад виправлення бери з чек-листа).

> Цей етап належить до паралельної фази B і виконується одночасно з етапами 2–5, 7. Він читає ЛИШЕ scope з етапу 1 і НЕ залежить від виходів етапів 2–5, 7. Кореляція/дедуплікація з іншими етапами робиться на етапі 8.

## Інструменти
- `read_file` — читання доступного вмісту/метаданих, де можливо.
- `execute_pwsh` — запуск наявних read-only документних чекерів (без ремедіації).

## Домени перевірки (за skill `#Accessibility Audit Rules`)
- **Спільне**: title/metadata, мова, ієрархія заголовків, alt-текст, описові лінки, порядок читання.
- **Word (.docx)**: стилі заголовків, alt, заголовки таблиць, мова.
- **Excel (.xlsx)**: назви аркушів, іменовані таблиці з заголовками, alt графіків, обʼєднані клітини.
- **PowerPoint (.pptx)**: заголовки слайдів, alt, порядок читання, медіа-підписи.
- **PDF (PDF/UA-1)**: теги, порядок читання, alt, мова, доступні форми, закладки.
- **ePub**: семантика, nav-зміст, мова, alt, порядок читання.

## Алгоритм виконання
1. Якщо документів немає — оркестратор пропускає етап (`skipped`).
2. Для кожного документа визнач тип і застосуй відповідний набір правил.
3. Сформуй структуровані знахідки (`domain: document`).
4. Якщо формат неможливо прочитати інструментами — зафіксуй обмеження, не вигадуй результат.

## Формат вихідного файлу
```
# Етап 6 — Documents Review

## Оглянуті документи
- file.docx (Word), file.pdf (PDF/UA) ...

## Обмеження
- [напр. "PDF без тегів — потрібна ручна перевірка інструментом X"]

## Знахідки
- id: DOC-001
  severity / wcag / domain: document / source: documents-review / location: file:елемент / issue / impact / recommendation / confidence
```

## Acceptance Criteria
- [ ] Для кожного документа визначено тип і застосовано відповідні правила.
- [ ] Кожна знахідка у структурованому форматі (`domain: document`).
- [ ] Обмеження (нечитабельний формат) зафіксовано, результат не вигадано.
- [ ] Не запускались інструменти ремедіації/автовиправлення.
- [ ] Файл `output/06-documents-review.md` створено; документи не змінювались.

## Після завершення
Повідом користувача: "Етап 6 завершено. Ревʼю документів виконано, N знахідок. Переглянь output/06-documents-review.md. Бажаєш внести зміни перед продовженням? (Так/Ні/Зупинити пайплайн)"

## Важливо
- Read-only: документи не ремедіювати, лише рекомендувати.
- Не запускати жодних інструментів ремедіації/автовиправлення.
- Правила — skill `#Accessibility Audit Rules`.
